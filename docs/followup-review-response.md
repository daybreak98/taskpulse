## 发布前优先修

### 1. API 自检会误报模式切换成功 —— 已修

| 评审指出 | 修法 |
|---|---|
| 自检访问默认 8899，没从配置取端口 | `PORT` 改为从 `~/.taskpulse/config.json` 的 `ui.port` 读取 |
| 不校验切换结果 | 新增 `switch_to()`：POST 后**回读 `/mode`**，只有返回的 `source` 与目标一致才算成功；不一致时明确报「切换数据源未生效（当前 X）」 |
| 回落 WEB 有同样误报 | 同上，失败分支也会打印「切换失败」而不是「已切到 WEB」 |
| 登录脚本取数失败仍报成功 | 成功判据改为**实际取到会话列表**（`RESULT OK N`），缓存文件存在只作为线索；失败退出码 1 |

待补：自检自行解析 SDK/Python 依赖，与后台实际启动参数仍可能不同（后台用
`uv-args.txt`，自检写死 `--with ks-aimate>=1.4.0`）。建议后续让自检直接读
`~/Applications/TaskPulse/uv-args.txt`，本次未改。

### 2. 旧来源数据与跨份 WEB 样本仍能写入 —— 已修

**来源往返**：只比较 `api`/`web` 字符串识别不出 API→WEB→API。新增递增的
`_source_epoch`，每次 `set_source_mode` 自增；`poll_tick` 记录 `(mode, epoch)`，
落盘前比对，往返后旧样本会被丢弃。

**WEB 混批**：`WebProvider.begin_round()` 在每轮采样前把缓存**定格一份**，
`queue` / `queue_at` / `last_message` 都从同一份快照读，不再出现「旧队列 + 新时间」。

### 3. 换范围时覆盖别人的截止时间 —— 已修（这是本批最严重的逻辑错误）

`carried` 是函数级局部变量，在换范围分支赋值后，循环**后续每个会话**都会通过
`locals().get("carried")` 读到它，把那条会话的截止时间写到别人头上。

修法：`carried` 在每轮循环开头重置为 `{}`，并把 `locals()` 取值改成直接 `task.update(carried)`。

回归测试 `test_scope_change_does_not_leak_deadline_to_other_tasks` 复现并验证：
两个会话各有截止时间，第一个换范围后，第二个的截止时间必须保持原值。

### 4. 跳转失败仍返回成功并标已读 —— 已修

| 路径 | 修法 |
|---|---|
| AppleScript 失败 | `focus_tab()` 校验 `returncode`，非零返回 False 并记日志 |
| `open url` 兜底 | 校验退出码，失败返回 `"failed"`（不再是 `"opened"`） |
| 扩展回报 unknown 仍标已读 | `/cmd/ack` 只有 `result in (focused, created)` 才 `_confirm_open` |
| 过期命令仍聚焦 | 扩展侧把 `stale` 判断提到最前，过期命令一律不执行（与后端兜底互斥） |

### 5. 依赖失败发生在旧 App 被替换之后 —— 已修

安装顺序调整：**依赖校验提到文件替换之前**（新的第 3 步）。失败即 `exit 1`，
现有安装完全不动。

`launchctl bootstrap` / `kickstart` 不再全部 `2>/dev/null`：失败会打印服务名与日志路径。

实测：用假 `uv`（`python` 子命令返回 1）在隔离 HOME 跑安装 →
`!! 依赖安装失败…现有安装未改动` → 退出码 **1** → `~/Applications` 下没有任何文件。

待补：健康检查目前仍只要 `/state` 结构正确就报就绪，没有区分「首次取数」与「数据新鲜」；
评审建议的三态（服务在线 / 首次取数 / 当前数据新鲜）本次未拆。

### 6. 回环服务身份门 —— 部分修

- **密钥读不到时不再放行**：原来 `return True`，现在 `return False` 并记日志
  （fail-closed）。装机本身坏了应该在安装阶段暴露，而不是运行时开门。
- **看板页下发密钥**：仍保留。浏览器发不出自定义头，看板要可用只能由服务端注入；
  这是「保留网页看板」这一约束的必然代价。评审建议的「看板单独受控入口」需要先决定
  看板是否保留，本次未动。
- **WEB 上报携带消息内容**：未改。采集端仍上报最多 400 字的消息片段（用于限流识别）。
  建议在采集端先归类、只留类别，属于接口约定变更，需要和状态机一起改。
