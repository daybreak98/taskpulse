## 三、API 模式 401（跨机故障）

详细取证见 [api-mode-401-issue.md](api-mode-401-issue.md)。

**根因**：API 模式需要「本机完成过一次扫码 SSO 登录」的凭据缓存
（`~/.codeflicker/sso/.ks_sso/sso-state.json`）。它提供 dataagent 应用自有的
`userToken` / `dpUserToken`，是 OBO 票之外的第二层身份。

同机同版本同配置的对照实验：

| 条件 | 结果 |
|---|---|
| 缓存不存在（cookie=0） | 401 |
| 拷入工作机缓存 | 69 个会话正常 |

SDK 日志：换票与注头都成功，`fail_stage=post_login_api_401`（SDK 自己标注
`not SSO failure`）。

**曾被误判**：中途认为是 `ks-aimate` 版本问题（1.0.29 缺 `trustDomain` 能力）。
那个差异真实存在，但干净环境用 1.5.3 同样 401，所以不是成因。版本下限提到
`>=1.4.0` 保留不动（旧版确实缺域限票能力）。

**修复**：
- 新增 `api_login.command`：免 Node/npm 直接取 npm 平台二进制包（只依赖 macOS 自带的
  curl + tar），默认 `AGENT_BROWSER_HEADED=1` 在真浏览器窗口展示二维码，`--terminal`
  退到终端 ASCII
- `api_check.command` 一键自检 + 自愈：探测多端口凭据服务、解码票据身份与 `aud`、
  查登录凭据条数、用运行时同参数真取一次；失败自动切 WEB 并给出待办

**顺带修的**：SDK 默认 headless 取二维码后打印一段给「AI 助手」的 markdown，
终端用户根本看不到二维码——改成 headed 窗口展示（`a75d05c`）。
